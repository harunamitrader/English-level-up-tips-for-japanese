# 第6章：ライティング篇

ライティングは「読む・聴く・話す」と並ぶ英語の四技能の一つです。エンジニアにとっては特に重要です。GitHub の Issue・PR コメント・Slack メッセージ・技術ブログなど、書く場面は多くあります。

## 読む

ライティング力は読む量に比例します。

優れた英語の文章をたくさん読むと、自然に文体・語彙の選び方・論理構成が身につきます。  
技術系なら [Hacker News](https://news.ycombinator.com/)・[Medium](https://medium.com/)・GitHub の Issue コメント。  
一般文章なら *The Economist* や *On Writing Well*（William Zinsser）。

## 書く

読んだだけでは書けるようになりません。**実際に書くこと**が最速の上達法です。

- GitHub のコメントをまず英語で書いてみる
- 技術ブログを英語で書いてみる
- 日記を英語でつけてみる

完璧を求めない。最初は短い一文でも構いません。

## フィードバックをもらう

書いたものを誰かに読んでもらうのが一番成長が速い方法です。

- 英語圏のコミュニティ（Reddit・Discord・GitHub）に投稿する
- 言語交換パートナーに添削してもらう
- AI（後の章で詳述）に添削・改善提案を依頼する

## AIツールを活用する

ChatGPT・Claude などの AI は英語ライティングの強力なサポーターです。

活用例：
- 「この文章を自然な英語に直してください」
- 「より formal な表現に書き換えてください」
- 「この文の文法的な問題点を指摘してください」
- 「同じ意味の別の表現を3つ提案してください」

AI は即座にフィードバックをくれます。遠慮せず使い倒してください。

## クリックベイト（釣りタイトル）の誘惑に注意する

多くの英語コンテンツクリエイターは「釣りタイトル」を使います。  
英語力に関わらず、内容より本質を見抜く読者リテラシーを磨きましょう。

自分が書く側になるときも同様。**誠実に、伝わりやすく書く**ことが長期的な信頼につながります。

## まとめ

```
読む → 書く → フィードバックをもらう → また書く
```

このサイクルを繰り返すだけです。
